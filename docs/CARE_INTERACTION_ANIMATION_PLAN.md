## 1. 本轮目标与边界

让互动页的**喂食、玩耍、清洁、睡觉／叫醒**成为可看懂、有情绪、有身体参与的完整表演。即使遮住提示文字，用户仍能辨认正在做什么、接触是否发生、动作是否结束。丰富感来自注意、准备、用途动作、反应、停顿与收尾，以及重复使用时的自然变化。

本计划已完成评审并进入实施；功能代码与素材已完成，当前发布候选为 1.2.8。延续现有本地 PNG、React 和角色关节渲染体系；不另建动画引擎，不扩大为十三项用品全面重制，不增加小游戏或养成数值规则。金币、属性恢复、经验公式、库存与存档 schema 保持原有语义。正式发布单独授权。

基础照顾与用品共享技术，但拥有不同分镜：基础喂食是一顿小餐，基础玩耍是短小接球游戏，清洁是日常擦洗，睡眠是持续陪伴状态；不能仅把背包动画换个入口。

## 3. 推荐分镜

以下时长仅为待样片验证的设计预算，不是已实现配置。实施时最终数值统一登记到 [变量登记表](reference/CONFIGURATION_REGISTRY.md)，本计划改为引用，不保留第二份参数总账。

| 动作 | 主分镜及节奏 | 有限变化与性格 |
| --- | --- | --- |
| 喂食，时长见配置登记 | 发现小餐、眼睛亮起 → 双手接好碗／食物 → 低头闻一下 → 食物真实到嘴、第一口咀嚼 → 短暂停顿后第二口、吞咽 → 擦嘴、满足点头 → 放下并回到休息姿态 | 主版以小口品尝；变化版轻吹再吃／最后一口稍慢再开心点头。嘴、手、食物必须在关键时段接触；不能一直端着物品摆动 |
| 玩耍，时长见配置登记 | 盯住小球、身体蓄力 → 拍球后球才弹出 → 视线追踪、重心跟随 → 双手接住 → 偶有轻微接偏、惊讶后重新抱稳 → 小幅庆祝 → 收好球 | 变化版换手接球／球轻碰身体后抱住。球在场景空间运动，接触后速度转向，有重量和回弹；活动限制在窗口内，不驱动桌面长距离位移 |
| 清洁，时长见配置登记 | 看看需要清洁的部位 → 拿好湿巾／小毛巾 → 擦脸、闭眼让出位置 → 换到身体一侧擦洗 → 短暂停顿、轻轻抖干 → 检查自己、舒展 → 收起工具 | 变化版先擦脸后身体／擦到脸颊短暂眯眼再继续。身体转向配合工具；泡沫或水点少量且只在擦洗附近出现 |
| 入睡，时长见配置登记 | 哈欠 → 揉眼 → 接好小枕／抱枕 → 坐低侧靠 → 抱稳 → 眼睛渐闭、进入呼吸 | 变化版轻揉另一侧眼睛／抱枕调整后依靠。优先坐低侧靠，不用僵硬整张图片横转冒充躺卧；若样片不足以表现舒服姿态，再列最小局部补图 |
| 持续睡眠 | 安静低幅呼吸为底层；隔较长时间才调整抱枕、轻微侧靠或叶片下垂；两次强调之间有充分静止 | 不反复播放入睡、哈欠或起身；不是每个循环都翻身。场景枕头固定，抱枕跟随手臂，二者按素材设计明确选择 |
| 叫醒，时长见配置登记 | 缓慢睁眼 → 看一眼周围 → 伸懒腰 → 收好枕头 → 回到清醒姿态 | 变化版揉眼后伸展／先舒展一侧手臂。完成后直接进入当前有效状态，不被旧睡眠循环覆盖 |

完成范围为：三项短照顾及入睡／叫醒各有一个主分镜和至少两个可辨认的局部变化；睡眠有稳定循环与稀疏变化。变化共享关键接触与结算语义，不需要成倍新增整套素材。

四阶段分别偏羞怯、活泼、稳重、从容开心：通过预备动作、停顿、目光与庆祝方式区别，不只整体加速或放大。每次序列固定选择变化，逐帧重算不得随机跳版；会话内避免连续相同，重启不要求保存随机历史。

减少动态效果时保留可辨认的用途姿态、表情和有界过渡，取消弹跳、摇晃、飞散及频繁循环；不得仅剩文字。三档动画强度不改变消费次数、收益或主进程截止时间。

## 4. 状态与结算方案

### 一次请求，一次领域结算

拟增加照顾专用类型化结果（名称在实施时按现有类型风格确定），至少表达 `ok`、机器可读结果码、`state`、`message`。保留现有接口兼容性，避免无关经济接口被迫重构。

主进程统一入口依次完成：来源／参数验证 → 请求去重与运行时可接受性预检 → 领域在线推进及有效性判断、构造候选状态与动作实例 → 保存成功 → 公布成功事实、替换旧表演并广播。候选准备不播放、不修改已提交状态。失败仍接受领域自然时间推进，但不扣本次成本、不播放成功动作、不清除原有效表演。保存失败不宣告成功，不隐式再次提交；既有持久化机制的具体错误路径在贯通阶段核实并测试。

命令身份绑定来源和会话，主进程维护有界去重记录；同 ID 重试返回既有结果、不重播，新用户操作拥有新 ID。已经提交后若广播或表现失败，仅同步最新状态或降级显示，不退款、不重新结算。跨进程崩溃不承诺跨重启的命令恰好一次；重启只加载存档、不重放命令。未完成保存与 runtime 预检的异常不得隐藏成普通成功。

动画不是事务提交点。中途拖动、关闭窗口、缺图、掉帧或结束回调均不再次扣费、补发奖励、退款或重做成功动作。

### 重复点击与主动切换

- 面板请求未返回时禁用重复提交；主进程仍独立保证并发安全。
- 同一基础短动作进行中再次请求，推荐返回“正在进行”，不扣资源、不刷新截止时间。
- 不同有效照顾或用品命令允许替换旧表演；旧动作已成功结算，不退款。先验证新动作有效，再清除旧动作。
- 不建立自动消费队列，不因为前一个动画结束而自动执行积压点击。
- 拖动期间新的消费动作推荐拒绝为忙碌，不能先扣费再因控制器无法启动而吞掉动画；拖动可中断已开始的动作。
- 新运行时序列有唯一身份、开始时间和时长；旧定时器只能结束自己的序列。处理同种动作结束后重入、跨入口请求、广播先后与组件重挂载，不依据渲染帧数计时。

“同动作播放中拒绝重复”是本次推荐的新交互规则，随计划一并审核；不伪装成已有冷却机制。

忙碌只检查**当前有效基础短动作**，不是历史上尚未到原截止时间的所有动作：

| 请求顺序（每步为不同命令 ID） | 接受与结算 |
| --- | --- |
| feed → feed | 后者在前者仍有效时 busy，不消费 |
| feed → play | 各自满足领域条件则各结算一次，play 替换 feed |
| feed → play → feed | 各自有效则三次独立结算；旧 feed 已失效，不继续占位 |
| 基础照顾 → 用品／用品 → 基础照顾 | 新请求通过领域和动作权限预检才结算并替换；失败保留旧表现 |
| 用品 → 用品 | 保持既有规则，不在此项目新增冷却 |
| 同 ID 重试 | 返回既有结果，不视作新的用户照顾 |

跨入口的独立有效命令不能误判为同 ID 重试；重复响应不能驱动前端重播。测试须覆盖请求交错、当前序列过期及身份缓存边界。

### 睡眠逻辑与睡眠表演分离

睡觉命令成功时即进入原有 `sleeping` 逻辑并按原规则恢复精力；叫醒命令成功时即结束逻辑睡眠。入睡／醒来短片只表现状态转换，不延迟精力语义。

拖动只打断姿态，不隐式叫醒；落地后仍睡眠则回安静循环。成功喂食／玩耍／清洁按现有规则离开睡眠，失败保持睡眠。宠物睡眠、Windows 锁屏、系统挂起保持三种独立语义。

入睡途中可以明确叫醒；不得因短片忙碌让用户无法醒来。连续睡眠切换需要基于目标状态和请求身份处理，避免同一个命令被重复解释成两次反向切换；不新增持久存档字段。重启后睡眠档直接进循环，有限照顾和入睡短片不重播。睡眠循环定期提供安全姿态供成长／换装提交，不能无限等待。

拟采用明确目标 `asleep/awake` 的睡眠请求；同目标为无操作，不重播。旧 `sleep` 调用在统一入口兼容映射；各菜单捕获明确目标，避免迟到的切换把叫醒解释为再次入睡。运行时睡眠 generation 只用于使旧回调失效，不能作为是否睡眠的业务依据。只有明确叫醒命令成功完成 `sleeping → idle` 才播放醒来短片；成功照顾直接进入照顾，不强插醒来。

## 5. 中断与资源规则

| 场景 | 推荐行为 |
| --- | --- |
| 拖动／落地 | 拖动优先；旧手持物沿当前快照有界退场，不悬空复活；落地后按逻辑状态恢复 |
| 环境鼠标／键盘、自动散步 | 不覆盖主动照顾或睡眠；结束后恢复原有环境判断 |
| 新的有效照顾／用品 | 新序列替换旧序列；最多有界旧道具退场，不积累多个旧动作 |
| 桌面锁定／解锁 | 沿现有入口权限；取消不再可交互的短表演，保留已结算状态及睡眠语义；解锁不补播 |
| 前台全屏／Windows 锁屏 | 保持既有收益和环境抑制规则；短片按既定截止时间结束，回来不从头播放 |
| 系统挂起／恢复 | 清理短序列、退出快照和过期回调；恢复按真实逻辑状态重建，收益仍按现有离线规则 |
| 退出／重启／组件重挂载 | 退出清理计时与监听；重启不重放消费；同一运行中重挂载从主进程当前时间进入 |
| 成长／换装／旅行装切换 | 接触段冻结整套已提交视觉，安全边界原子提交，不混用新身体与旧手点 |
| 道具解码慢或失败 | 不演空握；使用无道具仍可辨识的身体／表情降级，不重播结算；过期加载结果不能复活旧动作 |

新增素材按真实缺口确定：候选为小餐具／食物接触片、日常擦洗工具、睡眠枕头；玩具优先复用现有本地资源。记录真实 PNG alpha、口／手接触锚点、图层归属、镜像方式与许可证来源。不能用粒子或静态漂浮道具代替角色参与；不大规模重画角色。角色关键层失败沿用整图 fallback，明确作为异常降级而非正常验收通过。

## 7. 开发顺序与交付闸门

1. **贯通与视觉样板**：核实请求、保存、广播和恢复链；完成类型化结果、命令身份、序列、所有睡眠入口统一和一个喂食主分镜。睡眠业务契约此时确定，后续阶段实现具体睡眠动画。交付原尺寸连续演示，验证入口到主进程再到正式 LivePet，而非仅离线求帧。
2. **用途接触**：完成玩耍、清洁主分镜和必要素材；验证手握、口部、擦洗和球的因果轨迹，确认四阶段都可成立。
3. **持续睡眠**：完成入睡／循环／叫醒及三个入口，验证拖动、照顾切换、挂起和重启，检查睡眠循环长期静谧与安全换装。
4. **丰富度与一致性**：补齐变化、阶段性格、三档强度、减少动态效果、成长／装扮／旅行组合，完成失败降级和反复打断。
5. **集成验收**：自动化、动态视觉、Windows实机分别形成证据；交付用户审核。用户明确发起正式发布后才执行安装升级与 Release 闭环。

任一用途接触样片不合格，先改分镜或最小补图，不先把问题复制到所有变化。完整完成以上范围才称“四项丰富动作完成”，只有主样板不算交付完毕。工期在贯通和素材测量后估算，不以文字评审承诺固定天数。

## 8. 验收清单

**行为正确性**：成功一次扣费／恢复；满属性、金币不足、精力不足、非法请求、拖动忙碌均不误播；失败不中断旧有效动作；连点和跨入口请求不重复结算；旧 timer、加载回调、跳帧和重新挂载不重播。睡眠恢复量、在线／离线规则和所有现有经济测试不变。

**动画正确性**：检查每段接触边界前后、收尾截止时刻、长时间跳帧、反向 seek、固定种子重放；同一道具只绘制一次；手点、口部和工具用途点分别验证，几何通过后仍需看真实像素。缩小时长时仍有合理阶段，越过截止时间直接结束，不延长以补播。

**视觉完整性**：四阶段 × 双朝向 × 三档强度 × 减少动态开关覆盖自动求帧；八装扮和四旅行装覆盖接触／极值／收尾关键帧。每项每阶段须观看原尺寸完整动态，另看变化版与睡眠长段；检查手穿物、工具悬浮、肩部断裂、遮脸、出框、脚底滑动和重复式机械摆动。不得靠整体缩小角色或道具掩盖越界。

**真实使用**：在目标 Windows 打包程序实际点击三个入口，录制真实动作；验证真实系统 DPI 100%／125%／150%／200%、跨屏、窗口边缘、前台全屏、锁屏、挂起和退出。Chromium 缩放模拟只算预检；无法实测项单独列为未验证，不能写成通过。

**性能与长期运行**：同机同场景对照现有版本，记录完整短片及持续睡眠的帧间隔、CPU、内存与定时器／订阅数；重复切换、打断、换装后无持续累积。具体预算在基线测量后固定，不能用单次短截图证明长期稳定。
