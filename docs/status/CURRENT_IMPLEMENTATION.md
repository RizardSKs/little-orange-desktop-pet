## 当前已实现

- Electron + React + TypeScript 的完全离线 Windows x64 桌宠。
- 透明桌宠窗口、独立管理面板、托盘、菜单、单实例和开机启动设置。
- 四项照顾属性、四种互动、在线与最多 8 小时离线收益。
- 20 级成长、四个外观阶段和八个本地装扮。
- 自动散步、三档强度、分层手脚步态、行为/需求/待机表情。
- schema 1 本地存档、临时文件、单份备份和损坏主档恢复。
- 1.0.0 完整安装/遗留 Portable 产物，以及 1.1.0 完整离线累积 Update。
- 6 个测试文件、20 项测试；2026-08-15 全部通过。

## 已知实现差距

### 存档与领域

- `validateSave()` 仅做浅层校验，没有字段级完整验证或 schema 迁移链。
- 加载时不核对成长阶段与等级是否一致。
- 离线结算摘要已计算，但加载流程丢弃摘要，界面不显示本次离线所得。
- 系统从休眠恢复时调用 `advanceOnline()` 而不是 `settleOffline()`，因此休眠时长当前按在线逻辑处理，不受离线 8 小时上限和 70% 折扣约束。
- `totalOnlineMs` 持续累计，但当前没有界面或玩法用途。
- 金币无上限；当前来源只有挂机，消耗只有喂食与装扮购买。

### 互动、动作与界面

- 动作只是行为字符串加复位计时器，不是含冷却、队列、资源和中断矩阵的完整状态机。
- `sad` 行为已定义，但当前业务流程不会主动进入。
- 前端重复维护部分互动结果文案，没有直接使用领域层返回的消息。
- 拖动只更新内存位置，松手没有专用立即保存动作。
- 装扮以 emoji 和一套 CSS 绝对坐标定位，没有按成长阶段区分锚点。
- `setPetPosition` 的公开类型返回 `void`，主进程目前实际返回坐标。

### 配置、工具链与发布

- 平衡数值分散在 `game.ts`、`main.ts`、`motion.ts`、`App.tsx`、`catalog.ts` 和 CSS。
- 依赖声明使用 `latest`；锁文件当前解析 Electron 43.1.1、electron-builder 26.15.3。可复现安装应使用 `npm.cmd ci`。
- 发布准则已确定不再发布新版 Portable，但当前 `npm.cmd run dist:win` 仍同时生成 Portable 和 NSIS，尚无 Setup-only 命令。
- 根目录现有 1.0.0 Setup/Portable 文件名不含版本号；当前 `package.json` 已配置后续产物使用版本化名称。
- `update-manifest.json` 的 `compatibleFrom: 1.0.0` 由脚本硬编码，程序不会读取，也没有自动兼容验证。
- 更新包未签名，可能触发 Windows SmartScreen 未知发布者提示。
- 仓库内没有 v1.1.0 GitHub Release URL 或远端三件套核验记录；本地归档也缺少同版本 v1.1.0 Setup，因此现有证据不能证明 v1.1.0 已组成符合新准则的完整正式 Release。
- 当前没有自动创建 GitHub Release、上传三件套或回读远端哈希的脚本，正式发布仍需使用已授权的网页或 API 人工完成。

### 仓库状态

- 根目录已初始化为 Git 仓库，默认分支为 `main`；可用提交历史从当前 1.1.0 文档基线开始。
- 私有远端 `origin` 指向 `https://github.com/RizardSKs/little-orange-desktop-pet.git`，基线提交使用 `v1.1.0` 标签标记。
- Git 无法还原基线之前的完整开发过程；1.0.0 到当前基线之间的历史事实仍须通过发布归档、清单和版本快照核对。
- `release/` 被 `.gitignore` 排除，版本事实必须通过现存产物、清单和版本快照核对。
- GitHub 现有 `v1.1.0` 标签指向最初源码基线；普通文档提交不会移动该正式版本标签。

## 待批准规划

以下只是候选后续任务，不是当前功能，也不自动获得实施权限：

- 集中并类型化可调配置，减少 UI 文案与领域规则重复。
- 增加深层存档校验、逐版迁移和真实旧档夹具。
- 展示离线收益摘要并完善时间推进语义。
- 建立动作状态机、分阶段装扮锚点和更完整的动画资源登记。
- 调整打包脚本，使 Setup 与 Update 符合新发布政策且不再产出新 Portable。
- 建立不改变应用离线边界的 GitHub Release 自动创建、三件套上传和远端核验工具。

亲密度、任务、成就、库存、多货币、多装扮槽位和小游戏等系统均未实现，也没有因出现在文档中而获得批准。
