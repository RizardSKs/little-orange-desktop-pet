## 1. 项目目标与本轮交付

让小橙子的动作更丰富，角色与每件道具的用途、接触位置和使用节奏更加一致，使用户能看懂“小橙子正在做什么”，并感受到期待、投入和满足。

最初交付仅为计划书；用户启动后，当前交付推进至四项技术样板。其余新增表现、阶段表情、动作变体和验收目标仍按里程碑实施，不代表已经全部完成；本次不打包或发布正式版本。

成功标准：道具去掉名称后仍能理解用途；身体、视线、双手和道具构成有因果关系的动作；重复观看有细节变化；四成长阶段、左右朝向和装扮组合均保持协调。

## 4. 统一表演准则

每项动作按“注意 → 准备 → 接触 → 使用 → 反应 → 收尾”编写分镜。它是设计描述，不要求把运行时状态机械扩展为六种新类型。

1. 注意先于动作：目光或头部先看向目标，随后伸手，避免道具已到嘴边角色仍无反应。
2. 接触具有用途：握杯身、抓刷柄、拍毛球表面、刷毛碰到身体；数学锚点与可见像素同时成立。
3. 身体响应力度：咀嚼轻压、喝水轻仰、拍球转移重心、刷理随接触轻侧身，避免所有道具使用同一种上下弹动。
4. 表情跟随节拍：准备时期待，使用时专注，完成时满足；不为每个小节强制新增素材。
5. 道具遵守空间归属：手持物跟手，场景物保持稳定，自由物有连续轨迹；获得和释放时不能瞬移。
6. 次级动作服务于主动作：叶片或身体轻微滞后只在现有素材允许时加入；粒子不能遮住脸和接触点。
7. 收尾可辨认：正常结束有放下、整理、回望等动作；用户拖动时立即服从输入，不等待表演结束。

以下为拟增强分镜，保留目录稳定 ID。实际素材是否足以支持每一步，须在样板阶段逐项核对。

| 道具及稳定 ID | 拟增强表演 | 匹配重点与可见验收 |
| --- | --- | --- |
| 橘香饼干 `item-citrus-cookie` | 看一眼饼干 → 双手捧起 → 小口咬食、停顿咀嚼 → 满足收手 | 手抓饼干边缘；饼干到嘴部才开始咀嚼；可选缺口片段体现进食，不能每次循环突然复原 |
| 蜂蜜汽水 `item-honey-soda` | 抱杯观察 → 杯沿接嘴 → 小幅倾杯与吞咽 → 放低杯子、空出一手擦嘴 | 明确杯沿与嘴部接触；双手和杯子一致；擦嘴前另一手稳定持杯 |
| 缎带毛球 `item-ribbon-ball` | 视线跟球 → 轻拍滚动 → 换手拦截 → 短扑后抱住 | 毛球以地面滚动、回弹为主；接触后轨迹才改变；不与羽毛共用可见运动节奏 |
| 泡泡浴券 `item-bubble-bath` | 看泡泡 → 左右搓洗 → 短暂停顿 → 轻甩水、舒展 | 手掌贴近脸颊或身体；泡泡从搓洗区域出现；保留眼睛可读性，不用泡泡遮盖动作 |
| 迷你键盘券 `item-mini-keyboard` | 拉入键盘 → 坐稳前倾 → 左右交替敲击、偶尔停顿思考 → 停手展示 | 手落在可见键区；键盘不随呼吸浮动；与环境键盘陪打保持规则兼容 |
| 鼠标逗趣羽 `item-mouse-feather` | 抬头跟随轻飘羽毛 → 试探挥爪 → 抓住羽柄 → 抱回观察 | 羽毛悬空轻飘，与毛球滚动区分；自由阶段不能表现为一直粘手 |
| 落日桌面主题券 `item-sunset-theme` | 发现暖光 → 抬手遮眼 → 转向欣赏、舒展 → 放手回正 | 暖阳作为场景效果，角色主动观看；使用表演结束后持续主题按原规则保留 |
| 阶段星辉券 `item-stage-sparkle` | 看双手 → 聚起星光 → 展臂展示成长阶段姿态 → 小幅致意 | 四阶段通过姿态与气质区分；星辉从手部动作发出，不替代角色表演 |
| 舒适护理券 `service-cozy-grooming` | 取刷 → 分段轻刷叶片和身体 → 抖松整理 → 检查后满意收好 | 手握刷柄、刷头贴被护理部位；如使用镜子，必须补齐独立素材和另一只手的握持分镜 |
| 桌边野餐券 `service-desktop-picnic` | 展垫坐下 → 取食、品尝 → 停顿环顾 → 整理餐具和餐垫 | 场景组合、可拿取食物分离；取食位置连续；食物变化不得隐含再次扣库存 |
| 闪耀派对券 `service-sparkle-party` | 拿好礼炮 → 准备发射并轻微后坐 → 踏步、拍手 → 挥手谢幕 | 礼炮方向正确；拍手前先放置礼炮；循环段交替安排踏步、拍手与停顿 |
| 皇家庆典券 `service-royal-celebration` | 整理仪态 → 正式鞠躬 → 双向皇家挥手 → 骄傲定格、回正 | 节奏庄重；与派对舞步明确区分；已装备皇冠时避免叠出第二顶皇冠 |
| 橙光盛典券 `service-grand-festival` | 开场致意 → 巡游踏步 → 分段展臂与庆典跳步 → 一次性终场 | 有段落递进；烟花围绕角色动作出现，不能全程遮挡；终场只在正常结束出现 |

## 6. 长服务、差异化与安静陪伴

长服务建议分成一次性开场、多个有变化的中段、一次性收尾。中段可采用固定顺序的小动作组合，避免每隔几秒重播完整入场。默认先用确定性编排；需要变化时基于动作序列选择少量变体，使截图、跳转时间和故障复现得到一致结果。

四阶段保留同一道具语义，拟用姿态幅度、停顿和收尾区分：萌芽偏小心试探，活力偏轻快，成熟偏稳定从容，闪耀偏舒展自信。这是待用户确认的表演方向，不新增惩罚性人格或养成数值。

减少动态效果时保留关键接触姿态、阶段表情和完成反馈，削弱或取消连续跳跃、旋转、闪烁和漂移粒子。三档强度调整幅度和次级运动，不改变握持点或道具用途。

## 9. 验收方案

### 9.1 逐项动态验收

每个道具保留完整播放片段和关键帧，覆盖注意、首次接触、使用峰值、释放及结尾；长服务必须观看完整时长，并检查段落转换。用正常桌宠尺寸观看，不能仅依靠放大截图判断。

每项记录“通过／返工／待观察”，并回答：用途是否可辨认？手接触的是正确部位吗？表情与动作同步吗？入场与收尾自然吗？循环是否机械重复？存在穿脸、手臂断裂、道具漂移或主要物件裁切吗？发现上述接触或遮挡缺陷即返工。

### 9.2 自动化与组合覆盖

- 基础动作覆盖 13 道具 × 4 阶段 × 2 朝向 × 3 强度，共 312 组；减少动态效果作为额外维度覆盖。
- 接触边界前后、循环边界、整段结束和动作替换点均求帧检查；增加刷头接触、杯沿到嘴、键区落手等用途约束，不能仅检查手与预设锚点相等。
- 全部永久装扮和旅行装参与几何边界扫描；视觉检查优先覆盖眼镜／耳机遮脸、围巾挡手、礼帽／皇冠碰叶片、背包／披风穿身体等高风险组合，并逐件登记结果。
- 回归连续使用同一道具、切换另一道具、拖动打断、超时、退出、成长切换、旅行往返、素材加载失败和减少动态效果切换。
- 在固定机器、相同设置下比较待机、普通用品和最长服务的帧时间、CPU、内存及图层数量；关注持续增长、周期卡顿和拖动响应。具体性能门槛在 M1 建立基线后写入权威参数文档，不虚构已测结果。
- 开发后先运行相关 Vitest，再运行完整 `npm.cmd test`、`npx.cmd tsc --noEmit` 和 `npm.cmd run build`；现有视觉脚本按其入口和环境要求运行。

### 9.3 真实环境与发布

在真实 Windows 系统缩放 100%、125%、150%、200% 下检查主体与道具；补充跨屏拖动、全屏场景和安装版逐道具观察。Chromium 缩放模拟只作辅助证据。

正式发布遵循 [发布与兼容准则](governance/RELEASE_AND_COMPATIBILITY.md)，保护旧存档、装扮、设置与位置；未经本轮实装验证，不沿用旧证据宣称新版本兼容。正式发布前同步用品动作、角色附件、素材、配置、测试和当前状态文档，并追加实际用户可见变更到更新日志。

## 10. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 数学上接触，视觉上仍像悬空 | 结合真实透明像素、原尺寸录像和人工判断；锚点测试只是其中一层 |
| 新表情破坏进食嘴部遮挡 | 表情、嘴部片段与角色阶段整套核对，缺图不强行展示 |
| 动作丰富后更吵、更机械 | 控制运动幅度，增加停顿，限定变体数量，减少动态效果独立验收 |
| 长服务最后突然消失 | 区分完整动作时间与内部周期，将收尾安排在现有结束时刻之前 |
| 道具数量增加或补图失控 | 本轮只覆盖现有目录，先列素材差距，再按样板结果决定必要补充 |
| 既有分支改进尚未实装验收 | 先建立动态基线；不把历史静态或几何结果当成本轮视觉结论 |

### 表 B：接触与遮挡

| 样板 | 接触关系 | 首版可见前后关系 | 限制与验收 |
| --- | --- | --- | --- |
| 汽水 | 双手到杯体；杯沿到嘴 | 身体后、杯体中、握持手掌前；饮用时专用嘴部覆盖按用途叠加 | 嘴部覆盖不掩盖错误杯沿位置；不强求手指绕杯前后穿插 |
| 毛球 | 接触爪到球面 | 接触时球后、爪前；自由轨迹与受控轨迹连续 | 轨迹转折对应视觉接触，不能先变向再拍中或突然吸手 |
| 护理 | 手到柄；刷头到选定前表面 | 身体／叶片表面后、刷具中、握持手掌前 | 刷头朝向可信；不反复跨身体前后，检查围巾、礼帽和旅行装 |
| 键盘 | 左右手到可见键区 | 场景键盘后、手掌前 | 身体前倾不带动键盘；接触不靠穿过键盘表达 |

单张 PNG 整体换层不等于局部穿插。优先现有图层，只有关键帧证明不足才最小拆片。镜像、四阶段、既有永久／旅行装均参与验证；不凭评审举例新增长袖等未核实目录项。

### 表 C：结束、中断与异步切换

| 情形 | 逻辑与视觉规则 | 终场与清理 |
| --- | --- | --- |
| 正常结束 | 总时长是截止点，收尾区间位于其内；使用整段时间求值，不无限重复中段直到超时 | 正常运行可辨认地收尾；不以到期为收尾开始信号 |
| 掉帧但尚未到期 | 直接求当前 elapsed time 对应的姿态，不能依赖逐帧触发事件 | 可跳过已错过的小节，不补播漏帧 |
| 严重卡顿跨过总时长 | 服从主进程最新状态，直接结束 | 不保证漏过的末帧被看见，不延长时长、不补播终场、不重复结算 |
| 拖动 | 输入立即优先，取消原分镜；已有消费结果不重算 | 持物／场景物允许有界快照退出，自由物取消，不演成功终场 |
| 成功使用新道具 | 新序列立即成为目标；不等待旧动作完整收尾 | 允许受控短暂退场并存，不能出现长期残留或使新动作等待旧终场 |
| 成长或旅行变化 | 逻辑可先变化；资源就绪、语义安全区间且退出快照清空后整套提交视觉 | 切换前保留旧完整组合，不混身体、锚点、尺寸、嘴部与附件，不触发额外终场 |
| 跨过安全点 | 安全条件按区间或状态表达，不依赖唯一瞬时帧 | 请求保留到下一合法区间；动作结束可在 idle 安全提交 |
| 资源慢 | 旧组合正常运行，不冻结动作等资源 | 若动作先结束，再等待资源与安全条件共同满足；不先提交半套 |
| 加载失败 | 沿既有失败降级处理，区分角色、附件和关键道具；不在渲染层改结算 | 不显示假专属成功、空握或错误混搭；不擅自退款 |

安全区间由分镜语义决定：尚未关键接触、已释放关键接触或 idle 等状态，再叠加资源就绪与退场完成条件。不能直接把旧周期百分比复制成新动作标准。失败或超时加载的最终降级需要在 M1 核对现有超时覆盖，不能把无期限等待当作成功。

### 表 D：幅度与安静度

| 类型 | 何时动、动什么 | 何时停 | 减少动态效果 |
| --- | --- | --- | --- |
| 微动作 | 注意、咀嚼、吞咽、检查中的表情和轻压缩 | 抑制无关运动；与用途相关的微动作可配合主体动作 | 保留关键表情，削弱持续摆动 |
| 主体动作 | 伸手、握持、刷理、敲击、拦截等用途动作 | 用途表达后进入反应、停顿或释放 | 保留接触与最小动作，降低重复和身体跟随 |
| 短暂强调 | 主动庆典或关键转折的短促展臂、后坐、跳步 | 峰值后回落，不持续贯穿长服务 | 改为清晰姿态或更弱重心变化 |
| 停顿 | 两段之间和使用后的满足、等待 | 下一项有因果的动作开始时结束 | 用停顿替代被削弱的强运动，总时长不因此延长 |

强度、重复和停顿调整须保持总时长、关键接触关系及可复现性，不改库存或收益。像素、角度、速度和性能门槛待真实边界与基线测量，实施时只在权威配置位置登记。
