# 发布与兼容性准则

> 文档级别：`LOCKED`  
> 修改权限：仅当用户在当前任务中明确点名本文件或明确授权改变发布与兼容策略时可改；本次创建授权不延续到未来，普通“更新文档”不构成授权。  
> 适用版本：`1.1.0` 起及后续正式版本；`1.0.0 Portable` 仅作为遗留例外。  
> 最后核对日期：`2026-08-15`  
> 权威来源：用户明确决策；`package.json`；`package-lock.json`；`electron-builder.update.cjs`；`scripts/write_update_manifest.mjs`；存档类型与实现。  
> 更新触发：用户明确改变发行物组合、更新模式、应用身份、兼容范围、存档迁移或稳定标识符策略时。

## 1. 官方发行物

从 `1.1.0` 起，每个正式版本只发布同一版本号的一组最新发行物：

- 完整安装包：`小橙子桌宠-Setup-x.y.z-x64.exe`。
- 离线累积更新包：`小橙子桌宠-Update-x.y.z-x64.exe`。
- 更新校验清单：`update-manifest.json`。

Setup 与 Update 的版本号、应用身份和程序内容必须一致。Update 是完整、离线、可累积覆盖的安装程序，不是联网下载器，也不是只适用于某一个前置版本的二进制差分补丁。

`1.0.0 Portable` 是遗留便携版，可保留用于历史归档，但不再制作、更新或作为后续正式版本的发行物。若现有构建配置仍含 portable 目标，它只代表尚待实现对齐的当前事实，不构成继续发布 Portable 的许可。

应用长期不联网检查、下载或自动安装更新。用户必须先正常退出应用，再手动运行最新 Update 或 Setup。

## 2. 稳定应用身份

以下值是覆盖安装和用户数据连续性的稳定身份，不得在普通版本更新中改变：

| 标识 | 固定值 |
| --- | --- |
| npm `name` | `little-orange-desktop-pet` |
| Electron `build.appId` | `cn.littleorange.desktop.pet` |
| Electron `productName` | `小橙子桌宠` |

改变任一值都属于产品迁移，必须获得用户明确授权，并在实施前给出安装识别、快捷方式、用户数据目录、卸载行为和回退方案。

## 3. 存档兼容

- 存档继续位于 Electron `app.getPath('userData')` 下，不得移入安装目录。
- 覆盖安装和普通卸载默认不得删除用户数据；更新配置必须保持 `deleteAppDataOnUninstall: false` 或等价行为。
- 已发布的存档字段不得直接删除、重命名或改变语义。新增必填字段必须有安全默认值；不兼容结构变化必须提升 `schemaVersion` 并提供从所有声明兼容版本迁移的代码和测试。
- 迁移前保留有效备份；迁移失败不得静默创建新档覆盖唯一可恢复旧档。
- 等级、经验、金币、装扮、设置和位置必须在升级后保持；数值规则更新不得误当作清档理由。

当前顶层稳定字段为 `schemaVersion`、`pet`、`growth`、`economy`、`settings`。其嵌套字段同样属于兼容协议；扩展时应优先采用带默认值的向后兼容新增。

## 4. 稳定装扮 ID

已发布装扮 ID 是存档协议的一部分：

- `leaf-clip`
- `bow`
- `glasses`
- `top-hat`
- `headphones`
- `scarf`
- `crown`
- `halo`

这些 ID 不得改名、复用给其他物品或在没有迁移映射时删除。名称、价格、解锁等级、视觉素材可以在相应 `LIVING` 规则中调整，但必须保证旧存档仍能识别已拥有和已装备内容。新增装扮应使用新的永久唯一 ID。

## 5. 版本与兼容声明

- `package.json` 与 `package-lock.json` 的根版本必须同步，并使用语义化版本号。
- `update-manifest.json` 中的版本、文件名、大小、SHA-256、应用身份和保留数据声明必须由实际发行物生成并核对。
- `compatibleFrom` 只能声明已经实际验证的最早兼容版本；不得根据代码阅读、推测或一次干净安装作出兼容承诺。
- 若某个旧版本无法安全直接升级，必须收窄兼容声明或提供经过实测的迁移路径，不能继续宣称任意旧版本可直升。

## 6. 发布验证门槛

正式发布前至少完成：

1. 运行全部自动化测试和生产构建。
2. 在干净 Windows 环境安装本版 Setup，验证启动、桌宠、管理面板、托盘、退出和新建存档。
3. 从清单声明的最早兼容版本，以及最新上一正式版本，分别运行本版 Update。
4. 升级前准备包含等级、经验、金币、已拥有及已装备装扮、设置和位置的存档；升级后逐项核对，并验证应用版本正确。
5. 核对 Setup、Update 与清单版本一致，校验 SHA-256，并确认运行期间没有更新相关网络请求。
6. 记录测试环境、源版本、目标版本、结果和已知限制；只有通过实测的范围才能写入兼容声明。

发布失败或验证不完整时，不得以“理论兼容”替代实测结论。
