## 快照结论

v1.1.0 本地留存了一个完整、离线、累积覆盖的 NSIS `Update` 安装程序及其校验清单。更新程序不联网、不自动下载，也不是二进制差分补丁。

本次审计没有在 `release/` 找到同版本的 `小橙子桌宠-Setup-1.1.0-x64.exe`。因此，本地留存的 v1.1.0 发行物集合不满足当前“每个正式版本同时提供同版本 Setup、Update 和清单”的治理要求；本快照记录该缺口，不把可重新构建等同于已发布。

经归档清单、编译产物和当前源码交叉核对，v1.1.0 的可验证变化包括：

- 新增 `motion` 模块并修改主进程与 preload 通道，用连续位置插值、朝向和运动状态驱动自动散步。
- 新增 `expression` 模块，将行为、低需求状态和待机抽样映射到表情。
- 为四个成长阶段各新增 `body`、左右手臂和左右腿五层 PNG；原有四张整图素材字节保持不变，并继续作为图层加载失败时的降级资源。
- 渲染资源发生变化，用于分层肢体步态、方向翻转和多状态表情。
- `dist-electron/shared/game.js`、`dist-electron/shared/catalog.js` 与 `dist-electron/main/store.js` 在两个归档中的 SHA-256 相同；归档证据未显示成长数值、装扮目录或存档读写规则随本版本改变。

审计时，当前工作区的主进程、preload、共享编译文件和 `dist/index.html` 与 v1.1.0 归档内对应文件逐字节一致。

## 兼容性与验证状态

- 更新配置继承稳定的 `name`、`appId` 与 `productName`，设置 `differentialPackage: false` 和 `deleteAppDataOnUninstall: false`。
- 存档仍位于 Electron `userData` 目录，当前结构仍是 `schemaVersion: 1`。
- 当前加载器只接受 `schemaVersion === 1`，尚无跨 schema 迁移链；未来改变存档结构前必须先实现迁移与失败保护。
- 2026-08-15 对当前源码补跑 `npm.cmd test`：6 个测试文件、20 个测试全部通过。该结果是事后审计结果，不是 v1.1.0 原始发布记录。
- 本次没有执行 v1.1.0 Setup 干净安装，因为对应产物不存在；也没有在安装过 v1.0.0 的隔离 Windows 环境中补做覆盖升级。
- 因缺少上述实装记录，`compatibleFrom: 1.0.0` 目前只能视为清单中的声明，不能提升为已由本快照验证的兼容承诺。

## 已知缺口

- 缺少同版本 v1.1.0 Setup，正式发行物组合不完整。
- 所留 Update 未进行代码签名，可能触发 Windows SmartScreen 的未知发布者提示。
- 没有配置发布服务、自动更新器或应用内清单校验；校验和分发均为人工流程。
- `compatibleFrom` 在生成脚本中固定为 `1.0.0`，尚未由发布流程根据实测结果约束。
- `release/` 被 `.gitignore` 排除，版本快照和外部归档必须承担发行历史记录职责。
