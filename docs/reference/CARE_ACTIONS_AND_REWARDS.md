## 当前已实现

### 照顾属性

PetStats 包含 satiety、mood、energy、cleanliness 四个数值。初始值见 CFG-004，等级相关上限见 CFG-013，时间变化见 CFG-014 至 CFG-018。

applyDecay 按 elapsedMs 一次性计算整段变化：

- 饱食、心情和清洁在清醒与睡眠时都持续下降。
- 精力在清醒时下降，在 sleeping 行为时恢复。
- 所有结果限制在 0 到当前等级上限，并四舍五入到两位小数。
- elapsedMs 非有限或小于等于 0 时返回属性副本，不发生变化。

属性归零目前不会死亡、离开、掉级、丢装扮或删除存档。其直接后果是降低挂机效率，并在没有更高优先级行为时触发需求表情。

### 互动动作

可从 IPC 调用的动作白名单见 CFG-035。每次 performAction 都先调用 advanceOnline，把动作发生前尚未推进的时间、衰减和在线奖励结算到当前时刻，再尝试动作。

- 喂食规则见 CFG-030。金币不足时不扣金币、不加属性或经验。
- 玩耍规则见 CFG-031。精力不足时不改变心情、精力、经验或行为。
- 清洁规则见 CFG-032。没有金币、最低清洁度或冷却门槛。
- 睡眠切换见 CFG-033。睡眠本身不发即时经验，但仍会参与时间奖励。

喂食、玩耍和清洁成功后设置临时 behavior；主进程按 CFG-034 复位。睡眠是持续状态，不被临时动作定时器复位。互动会取消当前自动移动。

当前动作没有冷却、每日次数、随机成功率、道具库存或实际恢复量检查。即使目标属性已经达到上限，只要其他前置条件满足，动作仍会消耗对应成本并发放经验。

### 在线推进与奖励

主进程按 CFG-044 周期调用 advanceOnline，然后保存并广播完整状态。advanceOnline 的顺序是：

1. 计算 lastUpdatedAt 到 now 的 elapsed。
2. 按当前 sleeping 状态处理整段属性变化。
3. 将 elapsed 加入 totalOnlineMs。
4. 将 elapsed 与 rewardRemainderMs 合并，按 CFG-021 拆成完整奖励单位和新余数。
5. 把 lastUpdatedAt 更新为 now。
6. 如存在完整单位，使用衰减后的属性计算 CFG-020 效率，再发放 CFG-022 和 CFG-023。

这意味着一个较长时间段按“整段结束后的属性”确定全部奖励效率，而不是逐分钟积分。

### 离线结算

SaveStore.load 在主存档、备份或默认存档中选出可用状态后，立即调用 settleOffline，并将结算后的状态重新保存。

- 累计上限见 CFG-025。
- 离线折扣与金币、经验公式见 CFG-026 至 CFG-028。
- 时钟倒退规则见 CFG-029。
- 离线期间照常按保存时的 sleeping 状态处理属性变化。
- 离线结算完成后 lastUpdatedAt 直接更新为真实 now，即使实际可奖励 elapsed 已被上限截断。
- OfflineSummary 包含 elapsedMs、coins、experience，但 SaveStore 当前只保留其 state。

### 经济循环

当前只有一种货币 coins：

- 初始余额见 CFG-007。
- 来源只有在线与离线挂机，见 CFG-022、CFG-027。
- 消耗只有喂食和购买装扮。
- 购买检查顺序为：物品存在、尚未拥有、等级达到、金币足够；成功后扣款并把稳定物品 ID 加入 ownedItems。
- 金币没有代码层最大值，也没有负数、非整数或非有限值的完整存档校验。

### 反馈与界面

状态页显示四项属性、当前上限、成长经验、挂机效率和距离下次在线结算的分钟数。互动页按当前金币和精力禁用喂食或玩耍按钮，并显示动作说明。

IPC 的 performAction 只把 SaveData 返回给渲染层，没有返回领域层生成的 message。界面当前自行维护成功提示，并仅对喂食金币不足做前端提示分支。

以下均未实现：

- 抚摸、连续点击、礼物、食物种类、小游戏或其他新动作。
- 动作冷却、每日次数、实际恢复量判定、收益递减或防刷经验规则。
- 亲密度、健康、生病、死亡、离家、负金币或掉级惩罚。
- 任务、成就、每日奖励、第二货币、真实付费或联网经济。
- 离线收益弹窗、逐时段积分式效率或在线/离线统一余数。
- 在主进程把结构化动作结果和唯一权威提示返回界面。

任何新增经验来源或金币来源/消耗，都应先评估对 CFG-011、CFG-022、CFG-023、CFG-027、CFG-028 及八件装扮价格曲线的整体影响。

## 失败与边界

- 清洁没有成本、冷却或“属性确实增加”的条件，因此可以连续点击，在清洁已满时仍反复获得经验。
- 喂食在饱食已满时仍扣金币并发经验；玩耍在心情已满时仍消耗精力并发经验。
- performAction 先做时间推进，因此动作最终失败也可能返回一个已经发生衰减或挂机奖励的新状态。
- UI 没有使用领域层 message。如果玩耍因状态竞争在主进程被拒绝，渲染层仍可能显示成功提示。
- 离线结算忽略离线时长与已有 rewardRemainderMs 的合并；原余数保留，但离线不足整周期的时间不会补齐它。
- 离线效率使用整段衰减后的最终属性；长时间离线不会按中途属性逐段结算。
- 应用从系统挂起恢复时调用 advanceOnline，不调用 settleOffline，因此该段时间没有八小时上限和离线折扣，并会进入 totalOnlineMs。
- sleeping 状态持续获得挂机金币和经验；只有精力变化方向不同，其他三项仍衰减。
- 离线摘要不会传给渲染层，用户无法确认本次离线实际获得值。
- validateSave 没有验证四项属性、coins、experience 和 rewardRemainderMs 的数值合法性。坏存档可能让效率、界面百分比或经济计算出现 NaN、负值或异常大值。
- sad 行为存在于类型和表情映射中，但当前照顾规则不会把宠物切换为 sad。
- 状态页“下次结算”直接使用 300000，而领域权威值在 REWARD_INTERVAL_MS；修改 CFG-021 时必须同步，否则显示会漂移。
