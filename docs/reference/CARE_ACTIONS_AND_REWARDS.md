## 当前已实现

### 照顾属性与时间衰减

`PetStats` 包含 `satiety`、`mood`、`energy`、`cleanliness`。初始值见 CFG-004，等级相关上限见 CFG-013，时间变化见 CFG-014 至 CFG-018。

`applyDecay()` 按传入的 `elapsedMs` 一次性计算整段变化：

- 饱食、心情和清洁在清醒与宠物睡眠状态下都持续下降。
- 精力在清醒时下降，在 `sleeping` 行为时恢复。
- 结果限制在 0 到当前等级上限，并四舍五入到两位小数。
- 时间非有限或小于等于 0 时返回属性副本，不发生变化。

属性归零不会死亡、离开、掉级、丢装扮或删除存档。它会降低在线陪伴效率，并在没有更高优先级行为时触发需求表情。

### 照顾动作与防刷规则

可调用动作白名单见 CFG-035。每次 `performAction()` 都先调用 `advanceOnline()`，把动作发生前尚未推进的在线时间结算到当前时刻，再检查动作是否有效。接口返回统一的 `{ state, message }`，界面显示领域层消息。

| 动作 | 有效条件和成本 | 实际恢复 | 经验 |
| --- | --- | --- | --- |
| 喂食 | 饱食未满且金币至少 5；成功后扣 5 金币 | `min(25, 上限 - 当前饱食)` | `floor(3 × 实际恢复 / 25)` |
| 玩耍 | 心情未满且精力至少 8；成功后扣 8 精力 | `min(20, 上限 - 当前心情)` | `floor(8 × 实际恢复 / 20)` |
| 清洁 | 清洁未满；无金币或精力成本 | `min(30, 上限 - 当前清洁)` | `floor(4 × 实际恢复 / 30)` |
| 睡眠 | 在 `sleeping` 与 `idle` 间切换 | 无即时恢复 | 0 |

经验按“实际恢复量 / 标称恢复量”的比例向下取整。目标属性已满时，动作会返回明确失败消息，不扣金币或精力、不发经验，也不切换临时行为。剩余容量很小时，动作可能成功恢复属性但得到 0 经验；这是比例取整的预期结果。

喂食、玩耍和清洁成功后设置临时行为，主进程约 2.6 秒后复位；睡眠是持续状态。照顾动作会中断自动移动和环境互动。当前没有动作冷却、每日次数或随机失败率。

### 在线推进与奖励

主进程按 CFG-044 周期调用 `advanceOnline()`，并保存、广播完整状态。推进顺序为：

1. 计算 `lastUpdatedAt` 到 `now` 的正向时间。
2. 按当前宠物是否 `sleeping` 处理整段属性变化。
3. 把该段时间加入 `totalOnlineMs`。
4. 与 `rewardRemainderMs` 合并，按五分钟拆成完整奖励单位和新余数。
5. 把 `lastUpdatedAt` 更新为 `now`。
6. 若存在完整单位，以衰减后的属性计算效率并发放在线金币和经验。

效率为 `0.5 + 四项属性相对上限的平均值 × 0.7`，正常范围 0.5–1.2。在线金币为 `max(1, floor(单位数 × 2 × 效率))`，在线经验为 `max(1, floor(单位数 × 效率))`；这里的至少 1 是一次聚合推进的保底，不是每个单位分别保底。宠物处于 `sleeping` 行为时，只要应用仍实际运行，仍会获得在线奖励。

### 离线结算：零金币、零经验

`SaveStore.load()` 选出并验证可用存档后调用 `settleOffline()`，处理应用退出后的停机段；系统从 suspend、睡眠或休眠恢复时，主进程也走同一离线结算路径。

- 最多只按 8 小时处理属性变化，超过部分不继续衰减。
- 离线金币固定为 0，离线经验固定为 0，没有离线折扣或回流奖励公式。
- 不改变 `rewardRemainderMs`，不推进 `totalOnlineMs`。
- 不推进效果队列或探索任务；这些只按应用实际运行时间消耗。
- 按保存时的 `sleeping` 行为决定精力变化方向，其他三项照常衰减。
- 无论属性衰减实际截断为多久，`lastUpdatedAt` 都更新为真实 `now`，避免重复结算同一离线区间。
- 时钟倒退或无有效正向时间时不改变状态。

`OfflineSummary` 只包含 `elapsedMs`、`beforeStats` 和 `afterStats`，不再暴露金币或经验奖励字段。`SaveStore.loadWithSummary()` 把它返回给主进程，启动快照也会携带该摘要；渲染层当前不展示离线弹窗。

### 经济循环与金币消耗

当前只有一种货币 `coins`。金币自动来源只有应用实际运行时的在线奖励；离线、环境互动、键盘陪打和探索完成均不产出金币。照顾中的喂食、八件稳定装扮、十三种用品或服务券以及四种探索任务都会消耗金币，为长期存量提供持续支出入口。

用品或服务先购买进入背包，再由用户明确使用；探索开始时扣费，提前返回不退款。效果和探索只消耗应用实际运行时间，应用退出或系统 suspend、睡眠、休眠期间暂停。OS lock-screen 不算离线，也不暂停在线奖励、效果或探索计时；锁屏时只暂停原生鼠标/键盘互动和自动散步。具体目录价格、时长和效果以 `src/shared/catalog.ts` 为权威，数量和队列上限见 CFG-081 至 CFG-083。

每种用品和服务在成功使用后还会立即触发角色实际参与的专属动作；失败使用不会播放动作。动作编排、素材、优先级和验收以[用品与服务专属动作规格](INVENTORY_USE_ACTIONS.md)为权威。使用动作是非持久运行时表现，键盘、鼠标、主题和光环等长期效果仍由持久化效果队列负责。

### 非经济环境互动

鼠标注视、抚摸、连续点击、躲闪、拖动、落地、扒拉鼠标、追逐、眩晕和键盘陪打均是运行时视觉互动，不持久化冷却或采样数据，也不直接改变属性、金币或经验。桌面锁定、鼠标互动开关及键盘授权属于持久设置，但锁定本身不改变养成结算公式。

## 当前边界

- `performAction()` 先推进在线时间，因此动作最后失败时，返回状态仍可能包含动作前发生的衰减或在线奖励。
- 小幅有效恢复可能因向下取整得到 0 经验；满属性则完全拒绝动作和成本。
- 在线奖励按一段推进结束后的属性统一计算效率，不做逐分钟积分。
- 离线时长不与在线余数合并；原有 `rewardRemainderMs` 原样保留。
- `sleeping` 宠物只改变精力方向，不暂停应用实际运行时的在线奖励。
- 宠物行为 `sleeping`、OS lock-screen 与系统 suspend/sleep/hibernate 是三种不同状态：前两者仍可推进在线奖励，只有最后一种按离线零收益处理。
- 启动快照携带离线摘要，但渲染层尚未展示，用户只能从加载后的属性看到变化。
- `sad` 行为仍存在于类型和表情映射中，当前照顾规则不会主动切换到该行为。
- 状态页“下次在线奖励”仍以与领域常量相同的 300,000 毫秒显示；修改 CFG-021 时必须同步。
- 当前没有动作冷却、每日次数、亲密度、疾病、死亡、掉级、联网奖励、真实付费或第二货币。
