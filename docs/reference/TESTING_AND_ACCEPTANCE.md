## 当前已实现

### 本地基线

- Windows 10/11 x64。
- Node.js 22.12.0 或更高版本；当前锁文件解析的 Electron 43.1.1 声明该最低 Node 版本。
- 使用锁文件安装：`npm.cmd ci`。
- 单元与静态回归：`npm.cmd test`。
- 生产构建：`npm.cmd run build`。

### 变更所需最小验证

| 变更类型 | 至少执行 |
| --- | --- |
| 纯文档 | 链接和源码引用检查；`npm.cmd test`；`npm.cmd run build` |
| 成长、属性、收益、互动或商品规则 | 更新领域测试、变量登记表和对应规格；运行全部测试 |
| 动作、移动、表情或素材 | 领域测试、静态素材检查、桌宠窗口人工检查 |
| IPC、设置、窗口或托盘 | 类型检查、全部测试、开发环境人工操作 |
| 存档字段或 schema | 旧档迁移/回退测试、损坏档测试、覆盖安装验证；未满足不得发布 |
| 发布配置 | 全部测试和构建、产物元数据、清单、SHA-256、旧版覆盖安装 |

### 正式安装版验收矩阵

每个正式版本至少检查：

1. 干净环境安装最新版完整 Setup。
2. 从声明的最早兼容版本直接安装最新版累积 Update。
3. 从上一个正式版本安装最新版 Update。
4. 每条升级路径都核对等级、经验、金币、装扮、设置和位置。
5. 核对 Update 的版本、文件名、大小、SHA-256 和 `compatibleFrom`。
6. 核对 Update 不联网、不自动下载，且不是差分补丁。
7. 检查透明窗口、托盘、单实例、多显示器、DPI、全屏暂停、休眠恢复和正常卸载。

当前 1.0.0 Portable 是遗留产物，不再作为新版本发布矩阵的一部分。

## 失败与边界情况

- 自动测试通过不代表安装器、托盘、系统登录项或多显示器行为已验证。
- `compatibleFrom` 是发布声明，只有真实旧版升级验收才能证明。
- 项目依赖声明目前使用 `latest`；必须以 `package-lock.json` 和 `npm.cmd ci` 保持本次解析可复现，升级依赖属于独立变更。
- Git 历史从当前 1.1.0 文档基线开始，不能用它反推 1.0.0 到该基线之间的全部变化；早期历史快照仍必须依赖现有发布归档和清单。
- 未签名 EXE 可能触发 SmartScreen；该提示不能被误判为应用功能测试失败，但发布者必须核对文件来源和哈希。
