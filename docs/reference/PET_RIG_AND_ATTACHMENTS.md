## Phase 1：坐标与绘制

AssetSpace 是素材坐标，SceneSpace 使用相同的 512 逻辑单位，WindowSpace 是 220 DIP 窗口。`bodyMatrix` 将身体素材转入场景；`displayMatrix` 是唯一的阶段尺寸/位置转换，仅由 `RigRenderer` 公共根节点应用。场景物件不接受身体摆动。正反转换在 `geometry.ts` 集中实现。

`rigid-anchor` 使用完整姿态计算接触点，直接使用原始旋转分量组合无剪切方向，不从仿射矩阵反推。逻辑左右是原始未镜像素材的左右，镜像绕 512 场景中心执行。最终参数的文档权威入口仍为配置登记表。

每帧先验证并排序 `Drawable[]`；稳定 ID 的片段只渲染一个同级 DOM 元素。图层变化只改变该元素 slot，不跨父容器搬动或重复挂载。语义层名及顺序由 `RENDER_SLOTS` 定义。

`gateFrame` 是基础门槛的合成夹具，不是正式动作迁移。其所有位置及粒子由显式时间和种子计算。开发入口 `?view=rig-preview` 动态加载预览，不调用 App 的存档/IPC hook，生产构建不提供该入口。

## 验证与阶段状态

Phase 1 测试验证坐标往返、单次阶段缩放、镜像还原、刚性附件无剪切、片段唯一性、播放/seek/种子重放一致性。Electron 截图验证由 `scripts/verify_rig_preview.cjs` 执行，使用隔离用户目录及隐藏窗口，不运行正式主进程。

Phase 1 基础门槛通过后依次迁移。以下各阶段记录区分数学、素材、截图与正式界面验证，合成夹具结果不能替代正式角色验收。

## Phase 2 进展（2026-09-06）

用户明确授权 Python/Pillow 确定性编辑素材。prepare_rig_attachments.py 从基础提交读取原图，清理手臂残片、补肩根，并修正身体/腿部连接处残片；输出 stage-data.json 与八只手臂的 1448 个角度重叠验证。characterFrame 及其测试提供固定肩点和完整 fallback。隔离 Electron 四阶段/左右/四摆角共 32 帧通过，全量 104 项测试、类型检查和构建通过。正式动作时间轴及完整附件仍待后续迁移验证。

## Phase 3 进展（2026-09-06）

八件永久装扮使用 attachments.ts 的身体/头部锚点、明确姿态继承和分层配方。prepare_outfit_layers.py 无损拆分四种复杂装扮及四阶段叶片/身体，原图仍用于商店。四阶段×八装扮×左右方向共 64 帧通过加载及唯一绘制检查；人工修正耳机遮眼问题。素材对应的完整动作遮挡待 Phase 4 联合验证。

## Phase 4：接触动作（2026-09-06）

`actions.ts` 为全部用品、键盘和光标互动直接按显式时间求值。固定肩点、预制肘部偏置、手点和刚性道具由同一组参数生成；仅有限两段手臂，不引入 IK。握持期间手点由道具图形接触点生成，常规抬放插值原始位置参数，不插值仿射矩阵。护理刷具与光标箭头独立于旧组合图；野餐背景固定在身体后方的场景层，食物由左右手按循环交替拿取。饼干和饮料使用嘴部遮挡层。

`prepare_contact_parts.py` 输出透明接触片段、规范化道具并检查杯身、刷柄、羽柄、毛球和饼干上的真实 alpha。短纹理模板避免 Chromium 对长条纹理过度缩小时产生浅色拖尾；肩点、手点和横向粗细保持一致。线段端部截止于关节中心，圆形肘部与手掌分别绘制，避免长线段的端帽越过手掌。

动作周期、握持阶段与阈值的唯一数值登记见配置总账。Phase 4 隔离 Electron 生成 416 帧，位置问题通过场景位置、附件锚点及轨迹修正；没有动态缩小角色或主道具。握持数学、真实透明像素与截图分开验证。截图保存在 `tmp/rig-evidence/phase4/`，该目录不进入源码分发。

## Phase 5：旅行与视觉事务（2026-09-06）

`travel.ts` 为四种旅行装声明独立配方：挎包带/包体、雨衣、星空披风/领扣、大背包/肩带，共七张本地透明素材。柔性带子接受身体完整姿态，包体保持刚性，后背配件位于身体之后。旅行期间永久装备所有权不变，显示配方互斥；返程采用相同的加载事务。

`VisualState` 分离逻辑目标、待加载组合与已提交组合。过期 generation 的完成结果被拒绝。只有最新资源完成且动作位于释放后的安全边界，身体、肩点、表情、尺寸、接触与附件才能整套提交。失败旅行在安全点提交空附件，不能无限保留旧永久装扮。关键角色失败锁定当前阶段的整图 fallback，同阶段换衣不重试；新成长阶段允许重新加载。

状态测试覆盖整套原子提交、过期成功拒绝、失败旅行隐藏永久装扮，以及同阶段 fallback 锁定。旅行截图位于 `tmp/rig-evidence/phase5/`；四阶段、双方向、四旅行装共 32 帧。结合动作扫描后修正包带与雨衣的局部锚点。

## Phase 6：正式接入与回归（2026-09-06）

`PetView` 的拖拽、点击与原有 IPC 保留，`LivePet` 替换旧 CSS 角色/附件树。正式渲染每帧全部使用 committed stage，拖拽视觉作为显式输入；道具未解码或失败时不展示空握动作。减少动态效果切换只插值运动权重，手/物接触重新求值，不能剪切刚性道具。持物与场景中断快照在集中上限内退出；已取消自由目标和效果不复活。组件卸载取消 RAF，失效加载不提交。

验证脚本：

- `prepare_rig_hulls.py` + `verify_rig_bounds.cjs`：真实 alpha 凸包与每帧变换，覆盖三档强度、减少动态效果、全阶段/朝向、用品、环境互动和拖拽，以及所有永久/旅行附件。保存 `tmp/rig-evidence/bounds.json`。
- `verify_rig_preview.cjs --actions/--travel/--outfits`：静态直接求帧截图、图片解码及唯一绘制检查。
- `verify_rig_live.cjs`：真正挂载 LivePet，检查成长后不存在旧阶段图层、旅行资源故障后没有永久装扮残留，以及减少动态效果下绘制唯一性。隔离进程没有正式存档 API。

已在本机 Windows 原生显示缩放 125% 执行正式组件冒烟；另以 Chromium 强制缩放模拟 100%、125%、150%、200%。模拟不是 Windows 系统 DPI 切换验收。真实系统 100%/150%/200%、跨屏拖拽和安装版逐用品人工观察仍待补充；本次没有制作或发布安装包，不能把这些项目描述为通过。

本地截图供人工检查，自动断言只证明图片加载、几何边界和状态一致性，不能替代用户对美术与遮挡的最终接受。旧外围庆典、提示和等级装饰仍沿用既有 UI，不属于本次接触几何证明。

最终源码检查：116 项 Vitest、`tsc --noEmit`、生产构建通过。透明轮廓扫描 215,760 帧无越界；动作截图 416 帧、旅行截图 32 帧通过加载及唯一性检查。最终拼图为本地 `tmp/rig-evidence/final-review.png`。
